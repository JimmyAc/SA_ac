# POC 验证与交付

继承 [项目级验证规则](../.agent/VALIDATION.md)。本文件说明首个 POC 如何选择验收及记录证据；不会将建议 Must 自动批准为实现范围。

## 验收选择

下表 A/B 编号引用项目级验证清单，不另建不同语义的同名测试。

| POC 能力 | 按实际纳入范围启用的场景 |
|---|---|
| 首次离线与最小内容识别 | A01、A05 |
| 渐进索引、基础任务控制 | A02、A09 |
| L/实际副本与原件保护 | A03 |
| 最小属性与动态分类 | A04 |
| 命名人物、合照、未知和纠错 | A06 |
| 三态查询及排除未确认 AI | A07、A08 |
| 若明确纳入私密迁移 | B08—B10，并检查 B11 的普通 T 排除边界（如实现 T） |

T 及其他后续验证不自动进入当前 POC；后续范围明确后再启用对应 B 场景。

## 真实验证要求

- 清楚区分单元/集成测试、模拟器测试、目标真机及手工检查。
- 完全离线要覆盖干净安装/首次启动和资源交付，记录网络核查方法；缓存模型后的断网成功不能证明首次离线。
- 人物和内容识别使用真实模型及获准样本，记录模型版本、设备、样本规模、条件及错误；模拟数据仅作为隔离测试。
- 原件保护检查路径及字节未改变；重开恢复验证实际持久化。失败、取消、拒绝授权等不能只检查成功路径。
- 记录耗时、包体、内存及必要资源观察；没有已确认阈值时报告实测，不宣称量化性能验收通过。
- 通过的 POC 仅证明覆盖到的假设和条件，不代表完整产品或所有设备已经通过。
