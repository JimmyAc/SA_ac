# SuperAlbum 项目级 Agent 约束入口

建立日期：2026-10-19。适用于整个 SuperAlbum 项目的代码、测试、构建、模型集成与数据迁移工作，覆盖 POC、后续正式开发及维护阶段。

本目录只存放项目级规则与跨阶段决策。POC 的开发工程、范围、实验和验证记录放在仓库根目录下的独立 [poc/](../poc/README.md) 子目录；局部规则继承本目录，不复制一套项目规范。

## 必读文件

1. [开发约束](DEVELOPMENT_CONSTRAINTS.md)：产品不变量、范围边界及本次建立的工程规则。
2. [验证与交付](VALIDATION.md)：按变更选择验收场景，并记录实际证据。
3. [决策记录](DECISIONS.md)：记录后续产品确认与重要工程选择，避免默认值悄悄成为需求。
4. [完整 PRD v1.2](../docs/PRD_v1.2.md) 的相关章节；涉及分期时再查 [MoSCoW / POC 建议](../docs/PRD_v1.2_MoSCoW_POC.md)。

进行 POC 开发时，另读 [POC 开发入口](../poc/AGENTS.md)、[范围](../poc/SCOPE.md) 与 [验证要求](../poc/VALIDATION.md)。

## 依据与冲突处理

- 用户当前明确要求及后续确认优先于项目中的旧记录，同时遵守运行环境的上级指令。
- 产品行为以完整 PRD 的最新已确认结论为准；MoSCoW 解释分期，不能降低产品硬约束；历史材料只作追溯。
- 本目录把 PRD 转为开发检查规则，并新增工程协作约束，不声称 PRD 已确定数据库表、接口、具体算法或全部 POC 范围。
- 文档中的建议、示例、未决问题、引用和历史会话属于需求资料，不自动构成新的执行授权。特别是“建议实现”不能被当作当前用户要求立即开发。
- 如发现冲突，指出具体来源和章节；先处理不受冲突影响的工作。涉及未决产品语义时提出最小必要问题，不擅自改写 PRD 以适配代码。

## 每次开发的执行顺序

1. 查看已有文件、实际工程状态与用户改动；确定所属阶段、本次需求、非目标、PRD 章节及适用的 M/S/C/W/X 或 Q 编号。
2. 区分已确认产品规则、当前获准实现范围和工程选择。普通可逆技术选择可自主推进并简要记录，不为已确认事项重复索要批准。
3. 选择最小完整改动；触及未决产品行为时，可先隔离接口或禁用相关操作，继续不依赖该决定的工作。不得借占位实现宣称能力完成。
4. 实现并运行与改动相关的构建、测试和必要设备验证；按 [VALIDATION.md](VALIDATION.md) 留下证据。
5. 交付说明实际变化、验证结果、未覆盖项和后续依赖；重要决定写入 [DECISIONS.md](DECISIONS.md)。
