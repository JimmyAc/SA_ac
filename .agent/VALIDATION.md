# 全项目验证与交付约束

依据：PRD §11、附录 B，MoSCoW §3.1、§3.2 及 §4。

以下是整个项目各阶段共用的验证要求，**不是已执行记录，也不表示全部列入某一阶段**。每次按变更选相关场景；产品阶段未确定的能力不因出现在此表而获准开发。POC 的验收选择与实际证据要求见 [poc/VALIDATION.md](../poc/VALIDATION.md)。

## 验证层次

- 业务测试：稳定身份、属性/来源/核验、三态逻辑、计划意图和状态转换。
- 持久化与集成测试：真实读写、重开恢复、格式迁移、失败和重试；文件操作在可丢弃样本上验证实际结果。
- Android 设备验证：实际权限、首次断网、模型资源、解码、后台及系统备份边界。模拟器或模拟接口的结果须注明，不能代替目标真机效果结论。
- UI 检查：界面入口、交互、来源/状态可见性、筛选数量与无泄露；不能只验证数据层。

各阶段工程建立后，在对应开发目录记录实际可运行的构建/测试命令，执行前从工程中核对。POC 命令维护于 `poc/`；项目级文档保留共用验证规则。当前没有构建和测试入口，不提供假命令或通过记录。

## 每次交付留下的最小证据

1. 本次范围、对应 PRD/M/Q/场景编号，以及实际改动文件。
2. 实际执行的构建/测试或手工步骤，环境、设备及样本来源；结果为通过、失败、未运行或不适用，并注明原因。
3. 文件或数据库相关操作验证前后状态；中断、权限变化、部分失败及重试的观察结果。
4. 仍未完成的能力、待确认行为与环境限制。后续功能不因预留接口、模拟返回或静态审查而标记完成。

证据存放在当前任务的交付记录或项目后续约定位置，避免复制私人媒体和敏感日志。验证失败时先修复相关问题，再重跑相关检查；通过后不无故重复全量测试。
