# SuperAlbum 项目级代码开发约束

产品基线：[PRD v1.2](../docs/PRD_v1.2.md)；分期参考：[MoSCoW / POC](../docs/PRD_v1.2_MoSCoW_POC.md)。下列 C01—C10 为全项目产品要求的开发化表达；E01—E06 为工程规则，适用于所有阶段。未决事项保持未决，不以实现方便替用户定案。

## 项目范围与阶段关系

- **全项目范围**：以完整 PRD 为准，覆盖虚拟相册、本地 AI、人物/属性/事件、主动文件整理 T、私密空间、查询、输出及个人记忆延伸。完整需求不等于每个阶段全部实现。
- **阶段范围**：由当前任务及相应阶段文档确定。首个 POC 的主流程、建议 Must、暂不实施项及待定项统一维护在 [poc/SCOPE.md](../poc/SCOPE.md)，不以 POC 子集代替项目需求。
- **跨阶段约束**：功能暂不开发时可以缺少入口或实现；一旦实现，必须满足相应 C/E 规则，不以 POC 或原型为由降低原件保护、离线、隐私及一致性要求。
- **分期不等于删除**：MoSCoW 的 S/C/W 保留完整产品需求；未经当前任务纳入，不提前实现，也不专门搭建全部后期框架。
- **排除 X**：网盘与远程原件托管/备份同步及专门预留、顶层真实/虚拟双视图、普通分类复制整库、额外生物识别/全 App 锁/独立加密保险箱、内置内容编辑器、端侧训练及专门预留、强制完整视频时序能力及专门预留、通用文件管理器/社交平台/复杂账号体系。

排除项对应 MoSCoW §7；W 与 X 不可混同。用户后续明确改变项目范围或分期时，记录变化及依据。

## C01 平台、组织与交互

来源：PRD §1、§2.1—§2.2、§5、§10。

- 平台为 Android 原生，主要语言/UI 沿用 Kotlin、Jetpack Compose、Material 3。不得用网页或跨平台演示替代 Android 交付。
- Room/SQLite、WorkManager、MediaStore、适用的 SAF 是已有技术倾向；具体版本、最低系统版本、模块划分及模型后端尚未选定，采用时说明依据。
- 主页面统一使用虚拟属性、人物、时间和事件视图，按 L 展示；普通集合由属性和查询动态聚合，不另建普通静态相册成员表作为分类真相。
- 属性变化应反映到相关动态结果；查询、缩放、视图切换不产生照片或文件变更。
- 实现详情时保留全屏浏览、展开信息面板、只显示有内容项和添加入口；约 1/3 预览与 2/3 信息是需求方向，不冒充固定像素规范。
- App 界面使用照片、实际文件、整理计划等名称，不直接暴露 L/A/B/T 或数据库术语。项目学习目标通过协作解释实现，不加入面向用户的教学功能。

## C02 稳定身份与实际副本

来源：PRD §2.3、§2.6、§8.1、§8.2；V11-Q01。

- L 使用独立稳定标识；路径、URI、系统媒体 ID、哈希均不能单独充当 L 的永久身份。
- L 保存共享业务属性、人物/事件关系、来源与人工核验信息；具体文件保存自身访问标识、位置、可访问状态、文件特征和原文件元数据来源。不得给每份副本再建立独立业务属性真相。
- 完全相同副本可以关联同一 L，保留每份来源；相似但不同媒体保持独立 L。自动归并门槛和既有信息冲突不能从“共享方向”推导为已定案。
- App 主动 EXIF 写回后刷新各文件哈希并保持 L；不因暂时字节不同、部分写回失败或暂时访问失效而自动拆分/删除 L。
- 共享 L 不证明当前仍完全重复；去重前必须重新核验当前文件。
- 新发现且关联到隐藏 L 的副本立即继承 App 隐藏及禁止在线规则；其实际迁移状态另行记录。

## C03 原件、范围与执行边界

来源：PRD §2.1、§2.6、§2.9、§2.11、§8.2—§8.4。

- 浏览、索引、AI、普通属性修改和保存计划不移动、删除或写回原件，不为分类复制整库。
- 文件改动必须有明确实际对象、范围、预览及用户确认，并遵守系统授权；允许一次批量选择表达范围，不要求逐照片反复弹窗。
- 移动/删除只作用于明确纳入的文件，不因共享 L 扩大到任务外副本；从 T 移除、移除属性、删除文件、删除逻辑记录是不同动作。
- 不以父目录递归移动/删除绕过范围。整目录操作会影响未纳入内容时阻止该操作；来源仍有内容时不删除目录，不宣称目录已搬空。
- 普通内部整理不提供复制；明确的分享/导出，以及私密迁入迁出的必要临时复制、校验、源移除是例外。
- **以后交付 EXIF 写回时**：独立入口明确列出 L 全部已关联副本，可包含 T 外文件，不提供仅单副本写回；逐份记录权限、格式能力与结果，刷新成功项哈希。AI 不自动写回。
- **以后交付去重时**：重检字节重复及保留副本有效性，不删除最后可保留文件；不以去重作为整理前提，不因删除一个副本丢失 L 业务信息。

## C04 来源、人工核验与查询

来源：PRD §4.3—§4.5、§6；V11-Q05—Q08、Q14、Q22。

- 属性定义、枚举选项、对象上的值和属性视图分别表达；人物实体、事件及标签保留各自含义。
- 来源与人工核验使用独立信息维度，能够区分元数据、AI、人工。未经人工核验的相机时间不能被伪标为“人工确认”。
- 三态值为包含/不限制/排除：同类包含 OR、异类 AND、排除项逐项排除；某类只有排除项时不引入隐含正向条件。
- 默认 AI 信息参与查询；“排除未确认的 AI 推断”只排除相应信息贡献，保留原始元数据及人工信息，不按整张照片是否含未确认值过滤。
- 查询及相应数量/聚合遵循同一规则，按 L 去重；T 的文件范围与文件计数单独保留。显示当前条件、数量并支持清空。
- 简单结构化筛选走轻量路径，不强行启动 AI/向量计算；以后实现语义搜索时，相似度不能放宽明确条件。
- 人工确认事实优先于未确认推断；重分析不得以默认覆盖实现绕过尚未确定的否定/撤销规则。
- 未分析、失败、未知、低可信及确定不存在不能混称为“没有”。缺失时间地点及排除筛选的具体规则仍待决定。

## C05 首次离线与人物识别

来源：PRD §3、§4.1、§4.4—§4.5；MoSCoW M04/M05、§3.1。

- 必需模型、词表及运行资源随安装交付或预置；首次启动断网即可识别、命名、匹配及纠错，不依赖激活、首次下载或隐式云端回退。
- 内容识别与人脸检测、特征提取、身份匹配可使用不同本地模型；“识别有人”不能代替跨照片识别用户命名的人物。
- 用户命名后使用本地人物档案关联其他照片；合照允许多人，未知或不确定不强认，纠错与命名重启后保留。不要求端侧训练。
- AI 推理、产生候选、保存结果与人工核验分别处理；异常不能产生伪造的成功结果。
- AI 新定义或枚举直接入库还是候选仍为 Q22；实现时不以工程默认值替代该产品决定。
- 候选模型名、演示图片或模拟返回值不能作为识别已可用的证据。准确率、误认/漏认、耗时、包体和资源占用按真实设备实测，不编造指标。

## C06 私密空间（交付该能力时完整遵守）

来源：PRD §2.3、§2.11、§4.7、§9.1；V12-D07/D08。

- 隐藏按 L 覆盖全部已知关联副本及派生关联；普通搜索、封面、人物/事件、重复预览、统计、保存摘要等均不可泄露私密内容。
- 搜索触发入口后独立密码验证，密码不进入普通检索历史。解锁不自动授权普通 T 使用私有空间。
- 原件迁入内部**持久私有目录**，不能放缓存；逐份校验成功后才移除共享源，保留 L 及业务信息。未校验前不删除唯一可用原件。
- 分开记录 App 隐藏可见性、迁入/校验/源移除状态。共享残留、拒绝授权、空间不足或中断必须在授权空间显示未完成范围，不声称已物理隐藏。
- 首次启用及每次确认迁入前，显著告知并确认“卸载 App 会删除私密照片”；空间内持续可查并支持明确移出。不承诺卸载时再拦截提醒。
- 移出需密码授权、共享目标、空间和同名冲突检查、预览确认及校验；不能只改隐藏标记。默认移出目标尚未确定。
- 私密原件、缩略图、人脸特征、文本、上下文及关联硬性禁止所有在线使用；普通授权不能覆盖。系统云备份也必须排除，混合数据库同样适用。
- 普通分享/导出/备份不得无提示带出私密内容；App 数据备份不等于私密原件备份，不自行增加强制备份。
- 不承诺清除未知副本、其他应用留存内容或提供额外独立加密保险箱。具体密码/会话与迁移恢复细节按 Q12 处理。

## C07 T 的计划模型与界面（实现该能力时适用）

来源：PRD §2.4—§2.7、§2.9—§2.11。

- T 初始化映射授权及私密排除后的目录和具体文件；普通 T 排除隐藏 L、全部关联副本及私有空间。
- 按 T＋实际文件保存初始化归属、当前计划归属及本轮处理状态；不写入 L 永久属性/EXIF。同名不同路径的目录使用可区分引用。
- 初始化归属已有值仍属本轮未处理；明确安排或保留原位后才已安排。无移动差异不等于检查完成。
- 单文件至多一个最终移动目标。明确先后安排以最后一次替换；同批多目标冲突必须消解，不默默选优先级或创建副本。
- 待删除与有效移动意图不能并存；标记待删除不执行删除，也不靠先移动后删除化解冲突。
- 目标文件夹区与普通属性筛选分开；使用“计划位置”“当前草稿”“保存方案”“打开方案”“按当前目录重新开始”“同步到设备”等措辞。
- 新增照片不自动加入旧 T。旧方案在继续、打开、预览和执行前复核隐藏状态，不得据旧引用迁出或泄露私密内容。

## C08 T 的保存、打开、重置与同步（实现该能力时适用）

来源：PRD §2.8—§2.10；V12-D01—D06、D09/D10。

- 固定一组 **1 自动＋3 手动槽**，不按 T 扩容，不设额外完整计划历史绕过限制；快照只存引用及计划状态，不复制媒体、整套缩略图或模型。
- 自动槽在**每次正常退出 T 编辑时**保存退出时最新安排，不把每次修改自动保存写成产品要求；异常终止不等于正常退出。同步逐项结果必须独立及时持久化。
- 手动保存明确选槽及覆盖对象，自动保存不改手动槽；保存失败可见，不能用空白/损坏内容覆盖上一有效记录或显示成功。
- 继续恢复自动草稿；打开允许选择四槽，先取得目标快照再切换，防止退出自动保存先覆盖待打开内容。手动源方案保持不变。
- 打开保留目标意图，按当前可核验文件状态生成工作草稿；不回滚磁盘、不恢复已删除原件、不回滚 L 永久属性。
- 旧目标 X、已跟踪当前位置 Y 时显示 Y → X 的新安排，重新预览确认才执行；已在 X 不重复移动。已确认不存在与暂时无法访问分别处理，身份不明不猜测执行。
- 重置在明确放弃后按**当前**磁盘初始化，放弃未执行安排与处理状态，不撤销已执行操作，不改手动槽或 L；重置本身不额外自动保存，退出编辑才更新自动槽。
- 保存、继续、打开、重置均不创建实际目录或修改文件；独立“同步到设备”预览确认后才执行，非持续双向同步。
- 同步逐文件报告成功/失败/未执行与原因；重试核对当前实际状态，仅处理未完成项。停止后续处理不等于回滚已完成操作，不承诺跨文件原子事务。

## C09 渐进、权限与资源

来源：PRD §3、§9.2—§9.3、附录 A。

- 已索引即可浏览，不等待全量扫描或 AI；索引与自动分析分别控制，未变化内容避免无意义重算。
- 来源无法访问与确实不存在分别记录，保留逻辑信息；继续/执行时重新检查权限，不使用陈旧路径猜测对象。
- 任务支持与当前阶段相符的停止/继续、失败原因及重试；基础分析队列恢复不是完整 T 的四槽恢复。
- 前台优先、按需解码与分页加载、有限并发、取消与资源释放；模型按需加载，不让大量原图常驻。实现完整后台能力时，按设备负载、电量及温度调整任务策略；具体分期由阶段文档确定。
- 优先复用系统缩略图，避免冗余缓存；可重建缓存与用户属性、人物、核验、持久化成果、私密原件分开管理，清缓存不删后者。

## C10 联网、备份及输出（实现该能力时适用）

来源：PRD §4.1—§4.2、§8.4、§9.1；MoSCoW S05/W07。

- 普通媒体云端增强必须可选并授权，明确禁止优先，执行时检查范围，不能借共享 L 绕过限制；基础离线能力不得依赖云端配置。
- API 凭证安全保存，不进源码、日志、示例或测试快照；私密信息不进入联网上下文、诊断上传或系统云备份。
- 本地 App 数据备份、原件备份、T 计划槽分别说明；导入恢复需校验关联与完整性，不产生超过四个活动计划槽。
- 分享/导出明确实际来源、内容、目标、空间和冲突；附加 JSON 与原件写回分别处理。未决包装及私密本地备份不自行定案。

## E01 能力与依赖边界

- 按需分离 UI、业务规则、持久化、Android 文件访问及推理适配；UI 不直接组合文件删除、身份归并等高风险规则。
- 按 PRD 附录 A 的对象/值/关系、查询、计算、候选结果、外部操作及任务控制边界复用能力；A01—A15 不要求各建一个模块或服务。
- 不为每个页面复制一套 L/副本/筛选规则，不为已删除或未授权的后期需求搭专门框架。
- 优先最小可用设计，只有实际复用、隔离或测试需求才增加抽象；不在缺少工程时虚构固定目录结构。
- POC 源码、构建配置、实验及其验证记录统一放在仓库根目录的 `poc/` 中；项目级 `.agent/` 不存放应用源码。正式工程位置待对应阶段确定，POC 代码复用须先检查依赖、数据兼容及验证证据，不因原型运行过就直接视为正式交付。

## E02 一致性与恢复

- 对象、属性值、关系、来源和核验的相关更新保持一致；若使用数据库，以合适事务保护本地关联变更。
- 系统/文件操作不视为数据库事务的一部分；设计可核查的逐项状态，处理“文件已改但数据库尚未更新”等中断窗口，不能只靠单个成功布尔值。
- 持久化结构和计划格式演进须考虑已有数据及失败恢复，不用静默清库掩盖迁移问题；有持久化用户数据后提供相应迁移验证。
- 不吞异常，不把权限拒绝、模型失败、存储不足、取消和来源缺失都转换成空列表或成功。

## E03 技术与依赖决策

- 选依赖/模型前核对官方资料、许可证、离线资源、目标设备兼容及必要体积；实际采用后固定可复现版本和来源。
- 不假设某推理 SDK 天然首次离线。记录模型版本、资源交付方式及设备验证；许可证和分发条件不明时不声称可随包发布。
- 普通可逆实现选择由 agent 推进；模型/算法的选择不能伪造效果结论，产品未决语义不能藏在配置默认值中。

## E04 改动与数据保护

- 开发前检查实际工作区，保留用户已有改动；只改本次相关内容，不做无关重构或整库格式化。
- 开发、测试优先使用获准样本及可丢弃副本，不对用户真实媒体执行探索性破坏操作；App 内的用户确认流程仍必须实现。
- 不提交原始私人照片、人脸特征、人物真名数据、密钥、绝对私人路径或未脱敏日志；测试资料使用合成或明确可分发样本。
- 模拟实现只用于隔离测试或明确标注的原型，不能作为真实模型、文件执行或权限验证的交付证据。

## E05 完成标准

- 按 [VALIDATION.md](VALIDATION.md) 运行与本次变更相符的验证；没有环境、设备或依赖时如实写未运行及原因，不写“通过”。
- 涉及身份、查询、权限、持久化或文件执行的规则变更，增加能捕获业务错误的测试；不为纯文案等低影响改动机械堆测试。
