用户已确认产品行为，并选择 A：首个 POC 验证完全离线识别、人物关联和虚拟分类，T 后续验证。具体 Must 条目尚未全部批准。本文已同步 PRD v1.2 最新的退出编辑自动保存、旧方案恢复、目标文件夹分区、私密原件迁移及卸载告知规则；历史 review 和旧 MoSCoW 的边界不能覆盖这些决定。

### 本次同步摘要

| 变化 | 当前结论 |
|---|---|
| POC 主流程 | A 已确认，不再作为未回答的选项；T 不要求进入首个 POC |
| 自动保存 | 每次退出 T 编辑时保存当前草稿；不是每次修改都自动保存 |
| 方案打开 | 保留目标意图，结合当前实际文件状态生成工作草稿，原手动方案不被改写 |

| 私密空间 | 隐藏原件迁入 App 内部持久私有目录；用户接受卸载删除并要求明确告知；禁止在线及系统云备份 |
| 私密功能阶段 | 新方案包含实际原件迁移；旧 M07 不直接算作已确认 Must，其 POC 阶段继续待定，见 §3.2 |

## 1. 划分依据

| 分类 | 本文含义 |
|---|---|
| Must（M） | 建议的首个 POC 必须形成的完整演示闭环，缺少就无法验证本轮核心假设 |
| Should（S） | 对完整产品重要，可在首个 POC 之后补齐；不是删除需求 |
| Could（C） | 对首轮验证影响较小的体验或扩展，可在资源允许时加入 |
| Won't this POC（W） | 本轮 POC 明确不做，完整产品需求仍按 PRD 保留 |
| 已删除/不在产品范围（X） | 用户已撤回或明确排除，不是承诺以后实现的 W |

首个 POC 已选定 **扫描照片 → 本地识别和人物命名 → 人工纠错 → 按属性找回照片 → 重开仍保留结果**。可以限定一台设备、一批授权照片、少量属性类型及基础界面，以验证实际可用性。

**完整 T 整理工具列为 Should，首个 POC 后验证**，与用户选择 A 一致。其文件权限、真实执行结果、计划恢复和部分失败另行验证，不为了缩短首个 POC 改掉已确认的产品规则。

私密空间虽也涉及物理迁移，但属于之后更新的独立能力。用户接受其存储和卸载语义，不等于已经确定其开发阶段；本文既不自动将它加入首个 POC，也不替用户认定必须后置。

## 2. 所有阶段共同遵守的产品约束

这些约束不是可降级的功能优先级。某功能暂不开发，不代表可以违反其边界：

1. 主页面始终是虚拟属性视图；不恢复真实/虚拟顶层双视图，不导入复制整库来接管原件。
2. 本地 AI 从首次启动就完全离线，必要模型与资源随安装提供或预置；人物名称、特征和结果在本地，不能用云端识别替代。
3. 普通属性修改只改 App；不擅自移动、删除或写回原件。以后实现物理改动，仍须明确对象、预览、确认及逐项结果。
4. L 的业务信息共享，临时目录归属按 T 和实际文件区分。哈希不是 L 身份，视觉相似照片不直接合并。
5. 隐藏按 L 覆盖全部已知关联副本，普通入口不可见，搜索触发后密码进入。隐藏原件迁入内部持久私有目录，校验并移除共享原件后才宣称物理隐藏完成；部分失败可见，不承诺清除未知副本或其他应用已留存的内容。
6. 来源与人工核验分开。常用“排除未确认的 AI 推断”保留元数据和人工信息，不能把它们统一误标为人工确认。
7. T 一旦交付，应满足 1 自动＋3 手动槽、每次退出编辑时自动保存、自动/手动方案打开、继续、按当前磁盘重置、待删除计划和独立同步。打开方案保留意图并核验当前位置，手动源方案不被改写；暂缓整个工具不改变这些规则。
8. 前台可渐进浏览，不等全部 AI 完成；保留失败与可重试状态，避免原件复制、冗余缓存和大量原图常驻。
9. 私密功能交付时，首次启用及每次迁入前明确告知并确认“卸载 App 会删除私密照片”，空间内持续可查，支持明确移出。私密内容及派生信息禁止在线，也须排除系统云备份；既有数据库备份不等于私密原件备份，不额外承诺强制备份。
10. 普通 T 排除隐藏媒体及私有空间，旧方案不能绕过该边界；按已纳入文件执行，不递归处理未纳入内容，不把本次整理完成等同于源目录搬空。目标文件夹与属性筛选在界面上分开。

## 3. Must：首个 POC 的建议范围

| 编号 | 必须验证的能力 | 本轮建议的最小边界 | 对应 PRD |
|---|---|---|---|
| M01 | 获准照片的渐进索引与浏览 | 在一台目标 Android 设备上，选择有限来源范围；先支持该设备可解码的 JPEG/PNG 照片，读取时间及可用 GPS，已索引即可浏览；权限失效或文件不存在可见 | §2.1、§3、§5 |
| M02 | 稳定照片身份与实际副本 | 保留 L 和具体文件来源；在选定小规模样本中识别字节完全相同副本，主页按 L 展示，详情能看到实际来源；相似图保持独立；本轮不执行去重删除 | §2.3、§8.1 |
| M03 | 可编辑属性和虚拟分类 | 读取、添加、修改、移除照片属性值；最小文本及枚举属性、名称查找和基本定义管理；只显示有内容的信息项并提供添加入口；按属性动态聚合，不移动文件 | §2.2、§4.3—§4.4、§5.3 |
| M04 | 最小本地自动内容识别 | 选择一个可完全离线运行的轻量识别方案，对明确的小类内容生成可用属性值；记录 AI 来源与未确认状态，支持人工修改或确认。无需任意长描述、笑点解释或开放世界理解 | §4.1、§4.3、§4.5 |
| M05 | 完全离线的人物身份关联 | 检测人脸、提取特征、本地匹配人物；用户命名小明/小红，再在其他照片中关联名称；支持合照多人、未知或不确定及人工纠错。不是仅打“有人”标签 | §4.1、§4.4—§4.5 |
| M06 | 可用的属性检索与核验筛选 | 三态的同类 OR、异类 AND、逐项排除；显示条件和数量、可清空；按人物或属性找照片；默认采用 AI 信息，开关可排除未确认 AI，保留原始元数据及人工信息 | §6.1—§6.3 |
| M08 | 本地持久化与基础任务控制 | 重开后保留属性、人物命名及确认状态；识别渐进执行，状态、失败与重试可见，能停止/继续批量分析；使用适度缓存和按需加载，浏览不被全量任务阻塞 | §3、§4.5、§9.2—§9.3、附录 A |

沿用原编号便于追踪，M07 已移至 §3.2 的阶段待定项，因此本表编号保留间隔。上述具体 Must 范围仍为收敛建议，不将选择 A 解读为批准所有细节。

M03 的“基本定义管理”不要求一次做完别名、层级、合并、拆分；涉及已有引用的删除等未决规则不得暗中选定。可先限制操作并明确提示，具体行为作为 POC 细化项讨论。

M04 以预先明确的有限属性范围验证识别价值，不要求首版模型生成任意新属性定义。AI 新定义直接入库还是先候选仍为 V11-Q22；候选识别结果可以先复用已建立的属性库，避免提前决定该问题。

M05 不要求手机端训练人物模型。具体模型、阈值、大小与设备速度尚未选定或实测；模型是否满足首次离线和身份匹配要求，需要在 POC 中验证。内容识别与人物身份可以采用不同本地模型，不要求由一个通用模型包办。

M08 是识别队列的基础继续能力，不等于 T 的工作区计划、四个保存槽或完整本地备份。两类持久化对象不能混称为“保存已完成”。

### 3.1 Must 的演示与验收

| 场景 | 通过依据 |
|---|---|
| 断网首次使用 | 安装包或预置资源具备必要模型；断网启动、索引、识别与匹配可运行，无激活或模型下载依赖；记录网络行为核查结果 |
| 识别后分类 | 对真实测试照片产生至少一类有用的内容属性，可按该属性找到照片，人工修正后动态视图变化；原件字节及路径不因分类改变 |
| 小明与小红 | 先命名样本人脸，再处理其他照片，能形成跨照片关联；合照保留多人，未知不强认，错误可纠正且重开保留 |
| 人工核验开关 | 同一照片同时有相机时间、未确认 AI 主体和人工人物关联；开关只改变未确认 AI 的查询贡献，不整张过滤掉照片 |
| 重复与相似 | 两份完全相同文件共享业务信息、保留两份来源；另一张相似照片保持独立；本轮不删除原件 |
| 中断后恢复 | 重开仍保留用户信息，分析失败可以查看和重试；大任务尚未完成时能继续浏览已索引媒体 |

识别准确率、误认率、样本规模、延迟、包体、内存和耗电需要实测并记录，不在本次文档中编造通过数值。人物辨认、完全离线、可用分类是重点验证项；样本只证明覆盖到的条件，不能据小样本宣称所有设备和人脸场景已通过。

### 3.2 私密空间：需求已确认，POC 阶段待定

| 追踪编号 | 已确认产品需求 | 分期状态 |
|---|---|---|
| M07（沿用旧编号） | 原件迁入内部持久私有目录、全部已知副本范围、完整性校验与共享源移除、部分失败可见；搜索加密码、普通入口隔离；禁止在线及系统云备份；卸载删除明确告知并确认、支持移出 | 不再按旧版“仅 App 内可见性”估算，尚未确定纳入首个 POC，也未自动改列 Should |

若确定纳入 POC，须增加以下验收：迁入前用户看到卸载删除说明并确认；迁移校验和源移除结果可核查；失败不误报隐藏完成；普通入口和系统云备份不带出私密信息；移出私密空间有明确目标与确认。不能只实现密码页面和可见性标记就宣称完成新版隐藏需求。

T 的阶段与私密空间阶段分别判断；即使私密迁移先实现，也不因此将完整 T 提前。私密原件的独立本地备份仍待需求判断，不能从卸载告知自动推导为必做。

## 4. Should：首个 POC 后优先补齐

| 编号 | 能力 | 完整交付时的边界 | 对应 PRD |
|---|---|---|---|
| S01 | 完整 T 分类工作区与计划管理 | 初始化允许参与的普通文件归属，目标文件夹与属性筛选分区、计划位置唯一、未处理/已安排；1 自动＋3 手动槽、退出编辑自动保存、继续、打开自动或手动方案、按当前目录重置；旧方案以当前状态生成草稿，不改源手动方案或回滚文件/永久属性 | §2.4—§2.8、§2.10—§2.11 |
| S02 | T 同步落地与文件操作 | 创建必要目录、移动或重命名明确文件；预览冲突后确认，检查当前范围、权限与私密排除，保存逐项结果，部分失败和重试不重复执行；不提供普通内部复制，不递归处理未纳入内容或假称源目录已清空 | §2.1、§2.5、§2.8—§2.11、§5.4 |
| S03 | 可选重复清理与 T 待删除 | 批量选择保留/删除，支持加入 T 统一预览同步；重新核验字节重复与保留副本，范围外不连带处理，保留 L 信息，系统允许时使用回收站 | §2.9、§8.1、§8.3 |
| S04 | 常见媒体与来源补齐 | 视频基础播放及文件信息、常用图片/视频格式；更多授权目录、SD 卡与 SAF；调用外部编辑器、改动后索引更新、权限与暂时失效恢复 | §3.2、§5.5、§8.2 |
| S05 | 本地数据备份和基础输出 | App 数据的本地备份/恢复、系统分享及基础媒体/JSON 导出；明确实际来源、附加信息和隐藏边界，不混同原件备份 | §8.4、§9.1 |
| S06 | 日常批量管理与基础事件 | 批量属性和确认纠错；手动事件的增删改查与媒体关联、基础实体档案管理；明确逻辑记录删除及引用影响，保持共享信息与实际文件删除分离 | §4.4—§4.5、§5.4、§7.2、§8.3 |
| S07 | 完整后台与资源管理 | 稳定断点、按任务优先级及设备负载调整、缓存容量与分类清理、可选模型管理；不清理持久化用户成果 | §4.1、§9.2—§9.3 |

S01—S03 是同一真实整理工具的配套能力。可以分步研发验证，但不能把“只有目录映射原型”宣称为已经交付完整 T，也不能以 POC 为由在实际执行时省略确认、固定槽位或失败结果。

对 S03 的批量保留规则、S02 的重名冲突和 S05 的隐藏备份包装，仍需解决相应未决问题后再定实施方案。Should 是优先级建议，不是把未决默认值填成确认。

T 验证还须覆盖：保存方案原目标 X，A 后来已移至 Y、B 已删除，打开后展示 A 当前 Y 与计划 X、B 已不存在，确认后才执行新的 Y → X；访问失效不能误判为删除。重置本身不额外自动保存，退出编辑才写入自动槽；同步逐项结果独立记录，不等到退出才记录。
